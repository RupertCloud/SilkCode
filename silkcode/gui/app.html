Projects — how they work

A session works on exactly one project: the tree its file tools, git commands and test runs are confined to. Open as many sessions as you like — each can sit on a different project with a different model, side by side.

Open or switch project

  • Project (header) — switches the project this session is on. The conversation comes with you; only the tree changes.
  • ＋ (new session) — asks which project to run it on: a GitHub repository you have access to (cloned for you into ~/.silkcode/projects/) or a local directory. Recently opened projects are listed above both, including the one you launched on.
  • Terminal — silkcode ~/code/app, or /project inside a REPL session to switch without losing the conversation.
  • Opening the same project twice is allowed: the second session is read-only until the first releases the workspace lock.

Create a new project

A blank folder is a bad place to start an agent — no tests to run, no instructions to read, nothing to revert to. silkcode new scaffolds one that already runs and tests, then makes the initial commit. Open it here afterwards with ＋.

silkcode new --list
silkcode new todo-cli --template python-cli
silkcode new api --describe "Invoice API for freelancers"
silkcode new api -p "add a health endpoint and a test for it"

Teach the agent about this project

  • SILKCODE.md in the project root — layout, conventions, the test command, anything it should never do. Read on every turn; scaffolded projects ship one.
  • Repo map — built automatically, so the model knows the shape of the codebase before its first tool call.
  • Memory & skills — durable notes the agent writes itself, plus markdown playbooks it can follow (/memory, /skills in the REPL).

Verify and ship

  • The agent runs your suite instead of claiming success — pytest, npm, cargo, go and flutter are detected from the project's own files.
  • GIT DIFF shows exactly what changed; ↩ Revert undoes a whole turn from the checkpoint taken before it.
  • ⇧ Push pushes when you say so; the GitHub dialog can grant pull/commit/ push/merge for the session or auto-push after every turn.
  • 🐝 Swarm runs tester + critic + worker against this project until it scores 10/10.

If something is off

  • Read-only / lock banner — another session or GUI instance holds this project. Close it, or take over from the banner once it is idle.
  • The GitHub list is empty — sign in from the GitHub dialog (or run silkcode connect github); it only lists repos you can actually clone.
  • “no test framework detected” — add a suite, and record the command in SILKCODE.md so the agent uses it too.
  • “no initial commit — empty ident name” — git does not know who you are yet: git config --global user.email you@example.com. The project was created fine.

Improvement swarm

Three agents — tester (investigates failures), critic (prioritized suggestions), worker (implements them) — iterate on this project, scoring it 0–10 each round (test suite + hygiene), until it reaches the target, the score stalls, or you stop it. The worker asks you before modifying files or running commands — pick Yes to all to approve everything for the rest of the session.
